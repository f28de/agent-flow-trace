# 智能体流转轨迹（agent-flow-trace）

一个 PenguinHarness 插件包，内含一个工作台（workbench）`flow-trace`。安装到某个 Agent 后，
打开该 Agent 的任意对话，对话旁会出现「**流转轨迹**」标签页，用来**显示并记录本项目内
多个智能体之间的任务派发与产物流转轨迹**。

## 功能

- **流转图**：每个智能体一列，其下的会话为节点；`run_subagent` 派生的子会话用有向边
  连接（跨智能体的派发一眼可见），节点上标注产出的产物数量。
- **事件时间线**：实时记录每条被关注会话的 AMSP 记录摘要——任务开始/结束、用户提问、
  子智能体派发（含目标智能体与任务简述）、产物写入及其结果状态。
- **产物台账**：所有 `write_file` / `edit_file` 产出的文件路径、所属智能体与会话、
  写入时间和工具结果状态（成功 / 中止 / 失败）。
- **历史回填**：`host.subscribe` 不重放历史记录，打开标签页时会对已关注会话（最多最近
  活跃的 30 个）各拉取最近 10 轮记录（`GET /api/sessions/:id/messages?tailLimit=10`；
  `tailLimit` 是轮次而非记录条数）回填入账——按从旧到新的顺序灌入、每会话按配额只取最新
  若干条（回填总量不超过 4000 条事件上限），让服务端 FIFO 缓冲自然保留最新会话的历史。
  订阅被服务端回收重建后会自动二次回填补缺口。服务端对回填做形状校验（`payload.type`
  白名单、ISO 时间戳）、`origin` 只允许指向已关注会话、每会话 60 秒限一次，并用持久化指纹
  去重，重复回填不会重复计数。时间戳一律按「真实时刻」比较（带 `+08:00` 之类偏移也能正确
  排序），明显超前于当前时刻的记录会被拒收。
- **忘记单个会话**：关注列表中每项旁的「忘记」按钮会删除该会话的全部事件与派发链接并停止
  关注（「取消关注」只停关注、保留记录）。
- **记录持久化**：事件保存在该工作台自己的状态文档（`state.json`）里，刷新页面、重启
  服务后仍在；工作台重载时会自动重新关注仍在记录的会话。卸载插件（或删除该工作台）时
  记录随之删除。
- **一键导出**：`GET /export?format=json|jsonl|md`，页面上有三个导出按钮，生成带时间戳的
  JSON / JSONL / Markdown（中文）报告文件下载。

## 安装

本包是一个本地插件目录，在 PenguinHarness 服务器上执行：

```bash
penguin plugin install ./agent-flow-trace
```

也可以在 Web App 的「**插件市场**」页面用「**上传 zip 包**」上传本目录的 zip
（不含 `node_modules`、`.git`）。安装后在「**插件**」页面把 `agent-flow-trace`
安装到目标 Agent 上（安装的是整个插件，即它的 `flow-trace` 工作台）。

## 使用

1. 打开装有本插件的 Agent 的任意对话。
2. 点击对话旁的「**流转轨迹**」标签页。
3. 页面会自动列出本项目的全部智能体与会话（含子 Agent 会话），开始关注它们并回填最近的
   历史记录：点击「**关注全部会话**」可重新扫描并关注最新列表（「刷新」只重拉页面数据）；
   页面每 15 秒也会自动扫描新出现的会话并补关注、回填。
4. 观察流转图、时间线与产物台账；需要留档时点右上角的导出按钮；不想再保留某个会话的
   记录时，点它旁边的「**忘记**」。

## 工作原理

- 页面（`workbenches/flow-trace/ui/`）通过同源 Cookie 调用服务器公开 API
  （`GET /api/projects/:projectId/agents`、`GET .../agents/:agentId/sessions`、
  `GET /api/sessions/:id/messages?tailLimit=10`）取得智能体与会话清单及历史尾部，
  再经工作台自己的 `../api/watch` 把 `{sessionId, agentId, lastActiveAt}` 交给服务端模块，
  并把历史记录经 `../api/ingest` 回填（服务端做形状校验、`origin` 白名单与每会话节流）。
- 服务端模块（`workbenches/flow-trace/index.ts`）用 `host.subscribe(sessionId, listener)`
  实时订阅这些会话的 AMSP 记录流（`task_begin` / `task_end` / `tool_call` /
  `tool_call_output` / `text` / `subagent` 指针及带 `origin` 的子会话记录），
  折叠成结构化事件；状态在内存中读写、每 2 秒合并批量写回 `host.setState` 持久化
  （避免逐条整文件重写；无结构性变化的轮询不触发落盘）。服务端会回收闲置 30 分钟的订阅，
  工作台在订阅满 25 分钟、或超过 10 分钟无记录投递时自动退订重订。HTTP 路由：`GET /status`
  （带 `limits`）、`GET /flow?since=<seq>`（增量，带 `maxSeq` / `minSeq` / `epoch`，`epoch` 是状态纪元，`/clear` 时轮换，页面检测到变化即整体重拉）、
  `POST /watch`（单次最多接受 1 万条会话——真实项目远达不到，仅用于挡住病态输入；
  `sessionId` 限 128 字符，校验 agentId 属于本项目、
  关注上限 300 按会话最近活跃时间淘汰最旧，刚淘汰的 10 分钟内不自动重加）、`POST /unwatch`、
  `POST /forget`（删除单会话台账并允许其派生边重建）、
  `POST /ingest`（历史回填：形状校验 + `origin` 白名单 + 每会话 60 秒节流 + 单次保留最新 500 条；
  事件缓冲已满时，早于最旧事件的记录会被拒收并计入响应的 `stale`，防止旧记录复活挤掉实时事件；
  时间戳按毫秒比较，明显超前的未来时间戳计入 `rejected`）、
  `POST /clear`（清空并轮换 `epoch`，同时清空淘汰冷却）、`GET /export?format=json|jsonl|md`
  （导出在锁内只取快照，序列化在锁外完成，不阻塞轮询）。
  页面每 3 秒增量轮询，内容无变化时跳过重渲染；所有请求 10 秒超时保护。
- 只读取**本 Project 内**的会话；不会发起任何模型调用，也不会修改任何会话内容。

## 兼容性说明

- `host.subscribe` 是较新服务器的能力。在没有它的旧服务器上，不会产生新的实时事件记录
  （历史回填仍可用），升级服务器后自动恢复。
- 事件缓冲上限 4000 条（满载后允许 100 条写入余量再一次性批量裁剪，避免每追加一条就
  搬移整个数组）、派发链接上限 4000 条（均先进先出，淘汰最旧），单条文本摘要截断至
  240 字符（任务终稿摘要 400 字符、累积上限 800 字符），未配对产物调用上限 512 条（超出淘汰
  最早，并持久化进状态文档以便重启后仍能配对结果），避免状态文档无限增长。页面每 3 秒经
  `GET /flow?since=<seq>` 增量轮询（带 in-flight 保护与内容键渲染跳过；标签页隐藏时暂停轮询），
  每 15 秒扫描一次新会话并补关注/回填。
- 状态文档损坏（被外部改写、磁盘截断）不会让工作台打不开：启动时逐元素校验，
  坏元素直接丢弃，其余记录照常加载，必要时用「清空记录」重置。

## 已知限制

- **订阅会被服务端回收**：会话闲置且 30 分钟无任何记录发布时，服务端会主动结束订阅。
  本工作台在订阅满 25 分钟、或超过 10 分钟没有任何记录投递（可能已被非闲置原因结束）时
  自动退订重订（页面每 15 秒重发关注也会触发），重订之间的小窗口内到达的记录可能丢失；
  订阅重建后页面会自动二次回填该会话历史以补缺口。刷新页面不会重载服务端模块，
  但重发关注会重建订阅。
- **历史回填有范围**：只回填最近活跃的 30 个已关注会话、每个会话最近 10 轮记录中按配额
  取的最新若干条（总量不超过 4000 条事件上限）；更早的历史不会进入台账。订阅重建后会
  二次回填，但点过「忘记」的会话不再自动回填。
- **数据留存**：用户提问摘要、任务终稿摘要与产物文件路径会留存于工作台自己的
  `state.json`，脱离会话的生命周期——删除会话不会自动清理台账，需要用「忘记」（单会话）
  或「清空记录」（全部）；只有卸载插件 / 删除该工作台才会彻底删除。
- **老服务器降级**：没有 `host.subscribe` 的服务器上没有实时记录，只有历史回填与轮询渲染。
- **关注上限 300 个会话**：超出时自动淘汰「未在当前关注请求中且会话最近活跃时间最旧」的
  会话（保留其历史事件）；刚被淘汰的会话 10 分钟内不会因轮询自动重新加入，避免反复进出
  造成订阅抖动。
- **单个智能体超过 1000 个会话时只取前 1000 个**：会话列表接口分页上限为 1000
  （`?limit=1000`），超出部分本轮不参与自动关注与历史回填。
- **事件缓冲满后的回填保护**：缓冲满 4000 条时，`/ingest` 中早于最旧事件的记录会被拒收
  （响应 `stale` 计数），防止被淘汰的旧记录「复活」挤掉实时事件；缓冲不满时回填不受影响。
- **请求超时**：页面所有请求（工作台 API 与服务器公开 API）10 秒无响应即放弃，避免网络
  卡住时轮询标志永远卡死。

## 目录结构

```
agent-flow-trace/
├── package.json                  # 插件清单（npm 字段 + penguin 块，files 含 workbenches）
├── README.md                     # 本文件
├── LICENSE                       # Apache-2.0
├── icon.svg                      # 插件图标（纯图形 SVG，符合官方安全规则）
└── workbenches/
    └── flow-trace/
        ├── package.json          # 工作台清单：penguin.version（YYYY.MM.DD.N）+ penguin.modules + 标签页贡献
        ├── index.ts              # 服务端模块：订阅 AMSP 记录、批量持久化、HTTP API（/status /flow?since= /watch /unwatch /forget /ingest /clear /export）
        └── ui/
            ├── index.html        # 页面骨架（中文，aria-live 提示）
            ├── app.js            # 页面逻辑：拉取会话、关注、历史回填、增量轮询渲染、导出
            └── style.css         # 页面样式（跟随 --wb-* 主题变量）
```

插件包（`agent-flow-trace/`）上一级工作区里的 `tests/` 是本地开发用的校验/测试脚本
（**不属于插件包**，`files` 清单不含它，本地安装/打包时不会上传）。

- **历史回填的可信度**：宿主没有「读取会话历史」的工作台 API，历史由页面代取服务器公开
  接口后经 `/ingest` 提交；服务端虽做形状校验、`origin` 白名单（只允许已关注会话）和
  每会话 60 秒节流，但同一 Project 内的用户理论上仍可提交伪造记录——台账可信度等同于该
  页面，不宜作审计证据。

## 版本规则

- 插件版本 = 根 `package.json` 的 `version`（semver，当前 `1.0.4`）。
- 工作台的日期版本 = `workbenches/flow-trace/package.json` 的 `penguin.version`
  （`YYYY.MM.DD.N`，日期 + 当天序号，当前 `2026.11.06.2`）。修改工作台源码后请递增该版本号。
